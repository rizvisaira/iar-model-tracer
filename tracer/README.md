# tracer

The Python package shared by the scripts and notebooks. Import it with the repo root on `sys.path`. The scripts do this themselves; in a notebook:

```python
import sys
sys.path.insert(0, "/workspace/iar-model-tracer")
```

| module | contents |
|---|---|
| [common.py](common.py) | paths, label mapping, data index, image loading, RAR / VAR autoencoder loaders |
| [signals.py](signals.py) | provenance signals from Zhao et al. for one batch of images |
| [stage1.py](stage1.py) | `NearestFamilyThreshold`, the decision rule (used by Stages 1 and 2) |
| [metrics.py](metrics.py) | accuracy with a family / outlier / size breakdown, and confusion matrices |
| [generate.py](generate.py) | Stage 2: sample (tokens, image) pairs from the RAR / VAR generators |
| [inverse.py](inverse.py) | Stage 2: fine-tune the inverse decoder $D^{-1}$, evaluate it, load it into a tokenizer |
| [tokens.py](tokens.py) | Stage 3: recover tokens $Q(D^{-1}(x))$, per-image token-habit and token-histogram features |

## Conventions

- **Labels are strings**: `var16 var20 var24 var30 rarb rarl rarxl rarxxl outlier` (`LABELS`). The family is the label prefix: `FAMILY_OF["rarxl"] == "rar"`. `LABEL2IDX` gives the template's integer order. The package uses it only to validate folder names, and never converts labels to integers.
- **Images** are `[B,3,256,256]` float tensors in `[0,1]` on `DEVICE` (`"cuda"` if available).
- **Paths** are fixed in `common.py`: `DATA=/workspace/data`, `WEIGHTS=/workspace/weights`, `EXTERNAL=/workspace/external`, `CACHE=/workspace/cache`. Importing `tracer.common` also sets `HF_HOME=/workspace/hf_cache` if it is unset.

## common

```python
from tracer.common import build_index, load_batch, load_rar_tokenizer, load_var_vae, free

idx = build_index()          # DataFrame: split, label, name, path, family, key (11,050 rows)
x = load_batch(idx.path[:8]) # [8,3,256,256] in [0,1] on DEVICE
```

- `build_index()` lists every image under `DATA`, with labels taken from the class folder names. Row order is fixed (train, val, then test sorted numerically), and cached feature files are checked against it. `key = "split/label/name"` is unique; test rows have `label = NaN` and key `test//<n>.png`.
- `load_rar_tokenizer()` loads the MaskGIT-VQGAN tokenizer shared by all RAR sizes. It takes and returns images in `[0,1]`.
- `load_var_vae()` loads the multi-scale VQVAE shared by all VAR depths. It works in `[-1,1]`; `signals.var_signals` does the conversion.
- The two external repos both define top-level packages named `models`, `utils`, `data`, and so on, so **only one family's code can be imported at a time**. Each loader swaps `sys.path` and clears the clashing modules. Delete the first model and call `free()` before loading the other one.

## signals

```python
from tracer.signals import rar_signals, var_signals

tok = load_rar_tokenizer()
s = rar_signals(tok, x)        # dict of [B] tensors
del tok; free()

vae = load_var_vae()
s = var_signals(vae, x, n_iters=0)  # n_iters > 0 enables the Algorithm 3 token search (slow)
```

| key | meaning | paper |
|---|---|---|
| `quant` | $\lVert f - Q^{-1}(Q(f))\rVert^2$, latent quantization error | QuantLoss, Eq. 5 |
| `quant_p90` (RAR) | 90th percentile of the per-token quantization error | extra |
| `quant_greedy` (VAR) | `quant` with VAR's greedy scale-wise tokens; equals `quant` when `n_iters=0` | Alg. 2 |
| `enc1` | $\lVert \mathrm{Rec}(x) - x\rVert^2$ | EncLoss, Eq. 9 |
| `enc2` | $\max(\lVert \mathrm{Rec}(\mathrm{Rec}(x)) - \mathrm{Rec}(x)\rVert^2, 10^{-10})$, a complexity estimate. The floor only guards exact zeros, which appear when a fine-tuned $D^{-1}$ re-encodes $\mathrm{Rec}(x)$ to identical tokens; Stage 1 values are all above it | Eq. 10 denominator |
| `cal` | `enc1 / enc2` | calibrated EncLoss, Eq. 10 |
| `comb` (`comb_greedy`) | `quant * cal` | Eq. 11 |
| `tok_match` | fraction of token indices unchanged after re-encoding `Rec(x)` | extra |

For every loss, lower means more likely generated by that family; for `tok_match`, higher does. Squared norms are per-image means (MSE). Stage 1 uses the original encoder as $D^{-1}$; Stage 2 loads a fine-tuned one with `inverse.load_inverse`.

## stage1

```python
from tracer.stage1 import NearestFamilyThreshold

model = NearestFamilyThreshold({"rar": "rar_cal", "var": "var_cal"}, q=0.95, size_cols=feature_cols).fit(train)
model.family_z(df)        # z_rar, z_var
model.predict_family(df)  # "rar" / "var" / "outlier"
model.predict(df)         # full label strings
```

Inputs are feature DataFrames as produced by `scripts/extract_features.py`: one column per signal, plus `family` and `label` for `fit`.

1. **Standardise.** For each family, `z_f = (log s_f - mu_f) / sd_f`, with `mu_f` and `sd_f` taken from that family's own train images.
2. **Nearest family.** The family with the lower z wins; ties go to RAR.
3. **Outlier check.** The image is an outlier if that z exceeds `tau_f`, the q-quantile of the family's train z-scores. Train must contain no outliers.
4. **Size.** A per-family `StandardScaler → LogisticRegression` on `size_cols` picks the size; losses are logged first, `tok_match` is used as-is. With `size_cols=None`, it always predicts `rarb` / `var16`, as a baseline.

The fitted parameters are `mu_`, `sd_`, `tau_` and `size_clf_`, each a dict keyed by family.

## metrics

```python
from tracer.metrics import report, confusion, family_confusion

report(y_true, y_pred)            # dict of metrics (label strings in, floats out)
family_confusion(y_true, y_pred)  # 3x3 rar / var / outlier, rows = true
confusion(y_true, y_pred)         # 9-label, rows = true labels present
```

`report` returns `n`, `accuracy` (the task metric), `family_accuracy`, `outlier_recall`, `outlier_precision`, `size_accuracy_given_family`, and `family_recall_<f>` for each family present in `y_true`. A metric is NaN when its denominator is empty, e.g. outlier recall on train.

## generate (Stage 2)

```python
from tracer.common import load_rar_tokenizer
from tracer.generate import load_rar_generator, load_var_generator, sample_rar, sample_var

tok, gen = load_rar_tokenizer(), load_rar_generator("rarxl")
tokens, images = sample_rar(gen, tok, "rarxl", classes)  # [B,256] long, [B,3,256,256] uint8

vae, var = load_var_generator("var16")
tokens, images = sample_var(vae, var, classes)           # [B,680] long (10 scales concatenated), uint8 images
```

- `images` is always $D(Q^{-1}(\text{tokens}))$, the frozen decoder's output for the tokens, converted to uint8 by truncation ($\lfloor 255x \rfloor$), as both repos save their samples.
- Sampling uses each repo's ImageNet FID settings (`RAR_SAMPLING` per size, `VAR_SAMPLING`). The task's own settings are unknown.
- RAR's generator returns its tokens. VAR's `autoregressive_infer_cfg` returns only an image, so `sample_var` captures the tokens sampled at each scale and decodes them again in fp32. `return_generator_image=True` also returns VAR's own output, for checking.
- `split_var_tokens` splits the 680 VAR tokens into the 10 per-scale tensors.

## inverse (Stage 2)

$D^{-1}$ has the encoder's architecture, initialised from its weights. It is fine-tuned on generated pairs with $\mathcal{L}_\text{inv} = \lVert f_Z - D^{-1}(D(f_Z))\rVert^2$ (Eq. 6), with the codebook and decoder frozen.

```python
from tracer.inverse import LOAD_TOKENIZER, load_generated, split_holdout, finetune, evaluate_generated, load_inverse

data = load_generated("/workspace/cache/stage2/gen", "rar")    # tokens, images, classes, label, index
train, holdout = split_holdout(data, n_per_model=100)            # last 100 samples of each model held out
tok = finetune("rar", train, holdout, out_dir, epochs=10, batch_size=8, lr=5e-4)  # log.csv, last.pt, final.pt

tok = load_inverse(LOAD_TOKENIZER["rar"](), "rar", out_dir / "final.pt")  # tokenizer with D^-1 in place of E
evaluate_generated(tok, "rar", holdout)  # {"l_inv", "tok_acc", "quant"}
```

- `encode`, `target` and `quantize` give $D^{-1}(x)$, $f_Z = Q^{-1}(t_Z)$ and $Q$ followed by $Q^{-1}$ for either family. VAR's $D^{-1}$ is `encoder` + `quant_conv`, with the input scaled to $[-1,1]$.
- `load_inverse` overwrites the tokenizer's encoder weights in place, so `signals.rar_signals` / `var_signals` then compute every signal with $D^{-1}$.
- `finetune` uses Adam and StepLR (stepped per epoch), and logs one row per epoch to `log.csv`, where epoch 0 is the original encoder. Each row has the train loss, held-out `l_inv` / `tok_acc` / `quant`, and (`evaluate_task_train`) the AUC of each signal on the task's train images, own family vs the other. It resumes from `last.pt`.
- Token accuracy on VAR is capped: VAR's greedy quantizer does not always return $t_Z$ even from the exact $f_Z$.

## tokens (Stage 3)

```python
from tracer.tokens import recover_tokens, token_frequency, habit_features, histogram_features

tok = load_inverse(LOAD_TOKENIZER["rar"](), "rar", "/workspace/cache/stage2/inv/rar/final.pt")
t = recover_tokens(tok, "rar", x)                   # [B,256] long (VAR: [B,680], 10 scales concatenated)
freq = token_frequency(train_tokens, "rar")         # codebook-usage frequencies, from training tokens only
h = habit_features(t, "rar", freq)                  # DataFrame, one row per image
H = histogram_features(t, "rar")                    # scipy CSR [B,1024] (VAR: [B,4096]), rows sum to 1
```

- `habit_features` columns are prefixed with the family: `entropy` (bits) and `distinct` (fraction of distinct tokens) of the token histogram; `same_h` / `same_v`, the fraction of horizontally / vertically adjacent grid positions with the same token; and, if `freq` is given, `logfreq_mean` / `logfreq_p10`, the mean and 10th percentile of $\log$ freq over the image's tokens. VAR has these on the whole sequence and per scale (suffix `_s<p>`; adjacency on scales $\ge 4\times4$, the 1x1 scale skipped).
- Feature functions take numpy or torch tokens and run on the CPU. `python -m tracer.tokens` runs a self-test on random tokens.
